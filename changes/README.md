## Before opening them: things to check or decide

1. **Formatting.** `devel/Format_ZH.md` and CI require **clang-format 19.1.x**. The
   commits were formatted with `gf fmt` using clang-format **22.1.8** (the only one
   installed). Version 22 agrees with upstream's formatting on every file I checked,
   except one line (`operator tree ()`), which was excluded. Code *I wrote* has not
   been checked with 19. Install it (`scoop install llvm@19.1.0`, see the guide),
   run `gf fmt --changed-since=upstream/main` on each branch, and amend if anything
   changes. CI fails on unformatted C++.
2. **Titles.** The project prefixes titles and commit subjects with a task number,
   `[NNNN] summary` (e.g. `[6026] ...`). I do not have numbers; the PR texts use
   `[NNNN]`. `CONTRIBUTING.md` describes the numbering `x_y` and lists project 203
   (LaTeX import/export), 207 (performance), 201/221 (editor), 202/222 (UI),
   204 (typesetting), 200 (infrastructure) as the topic ranges. The commit subjects
   on the branches do not carry a prefix yet; add it with `git commit --amend`.
3. **Developer document.** `CONTRIBUTING.md` says each PR needs a document under
   `devel/` (`x_y.md`). `CLAUDE.md` in the repository says that is no longer
   required. The two disagree; check what recent merged PRs do.
4. **AI disclosure.** Every commit ends with
   `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`, and every PR text opens
   with a plain-language "What happened" and closes with "How this fix was made": human-aided
   debugging, code written using Claude Sonnet 5.5, reviewed and tested by you. That
   sentence says *you* reviewed and tested the work, so only submit once that is true
   (see item 5). The issue text is not a fix and has no such section.
5. **Confirm by hand before posting** (I could only test these headlessly):
   PR 2 (toolbar follows `$$` and Ctrl+Tab), PR 6 (a `gathered` block looks right on screen).
   Each PR text says what was and was not checked; keep it true.
6. **Base.** Re-run `git fetch upstream` and compare `upstream/main` with `c68a494fc`.
   If it moved, rebase the eight branches.

## What is deliberately not in the PRs

- Your keybindings (`$`, `$$`, `Alt+Up/Down`) are configuration, not Mogan source.
- The local conversion tests (`../tests/headless-conversion`) use a bash script and
  are not in the project's test layout. PR 4 offers to port them.
- The macOS and Linux behaviour of everything is untested; all work was done on
  Windows 11 with a Qt 6.8.3 debug-info build.

## Keeping this folder in step with the branches

Every `pr/*` branch has a PR text (`pr-N-<name>/pr.md`) and a bug report (`pr-N-<name>/bug.md`) in its own directory; add both when a
new PR branch is created. The branch names and the commit hashes of PRs 1-8 in the first table are
from before the branches were renamed to `pr/<name>` (for example `amsmath-gathered` is now
`pr/amsmath-aligned-gathered`, commit `115c45b0e`); check with `git log pr/<name>` before relying on them.


## Patch files

In each change's `patches/`, generated from its `pr/*` branch by `../scripts/make-patches.sh` (re-run it
after a branch changes). The `patches/README.md` there names the exact upstream commit the series
applies to, so it can be applied or ported after the branch is deleted.
